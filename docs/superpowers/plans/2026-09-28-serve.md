# tickstore serve — implementation plan

Spec: `docs/superpowers/specs/2026-09-28-serve-design.md`
Branch: `feature/serve`. TDD: a failing test precedes each task's code. Gate after
every task: `go build ./... && go vet ./... && go test ./...`.

## Task 1 — `server` package: response DTOs + tick mapping

- New `server/handler.go`: package `server`; define `tickDTO{TS,Price,Qty,Side}`
  with JSON tags (`ts,price,qty,side`), `side` as `"buy"`/`"sell"` string; a
  `toDTO(tick.Tick) tickDTO`; and the two response structs (`rangeResponse`,
  `lastResponse`).
- Test `server/handler_test.go`: `toDTO` maps Buy/Sell to the right strings and
  fields; JSON of a response has exactly the expected keys and an **empty list, not
  null**, when there are no ticks.

## Task 2 — `Handler`: routing + `/healthz` + validation skeleton

- `func Handler(s *store.Store) http.Handler` using `http.NewServeMux`.
- `GET /healthz` → `200 ok` (text/plain). Non-GET → `405`. Unknown path → `404`
  (JSON error).
- A small `writeJSON`/`writeErr` helper (sets `Content-Type`, status, encodes).
- Tests (httptest): `/healthz` ok; unknown path → 404 JSON; POST → 405.

## Task 3 — `GET /v1/range`

- Parse `symbol` (required, else 400), `from` (default MinInt64), `to` (default
  MaxInt64); non-integer → 400; reject `n` present → 400. Call `s.Range`, map
  `error` → 500, `nil` → empty list; encode `rangeResponse`.
- Tests: happy path with seeded store (boundaries `from<=TS<=to`), `from>to` → 200
  empty, unknown symbol → 200 empty, missing symbol → 400, bad `from` → 400,
  `n` present → 400.

## Task 4 — `GET /v1/last`

- Parse `symbol` (required), `n` (required, integer, `>= 0`; `<0` → 400); reject
  `from`/`to` present → 400. Call `s.Last`, map errors as above; encode
  `lastResponse`.
- Tests: happy path, `n` larger than log returns all, `n=0` → 200 empty, missing
  symbol → 400, bad/negative `n` → 400, `from` present → 400.

## Task 5 — `cmd/tickstore serve` subcommand + graceful shutdown

- Add `serve` case: flags `--dir` (default `data`), `--addr` (default `:8080`).
  `runServe(dir, addr) error` builds `store.New(dir)` + `server.Handler`, starts an
  `http.Server`, and blocks until SIGINT/SIGTERM, then `Shutdown(ctx)` with a short
  timeout. Clean shutdown returns nil; a real listen error returns non-nil.
- Update `usage()` to include `serve`.
- Test `cmd/tickstore`: bind `127.0.0.1:0`, serve in a goroutine, `GET /healthz`
  and `/v1/last?symbol=...&n=..` against the real port, then trigger shutdown;
  assert 200s and a clean stop. One smoke test only.

## Task 6 — manual e2e + README/AGENTS note

- Manual: ingest via the pipe, `serve`, `curl` range/last, diff against
  `tickstore query`. Confirm `.idx` still used (unchanged read path).
- Update README usage with a `serve` example and the endpoint table; add a line to
  AGENTS.md commands. (README/AGENTS currently live in the open docs PR; if that has
  merged, edit in place; otherwise add the serve section here and note the overlap.)
- Whole-branch review (fresh reviewer), fix Critical/Important, then open PR (base
  main) via `as-personal gh pr create`. Never self-merge.

## Notes

- No third-party deps; stdlib `net/http`, `encoding/json`, `os/signal`.
- `server` stays pure of process concerns (no `os.Exit`, no signals, no `Fatal`);
  all of that is in `cmd`.
- Reuse the existing `minInt64`/`maxInt64` consts from `cmd` by defining local
  equivalents in `server` (don't export CLI internals); keep the default semantics
  identical to the `query` subcommand.
